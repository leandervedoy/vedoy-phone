API blocks for the whole call stack.

Dette er hentet fra Vedoy Connect-serveren i prosjektet. Alle `/v1`-ruter krever Supabase JWT. Twilio-webhooks valideres med signatur og bruker serverens offentlige base-URL.

Readiness endpoint for the Node API. Returns service name and `ok: true`.

publicmonitoring

Vends short-lived Twilio Voice access tokens for iOS or Android development builds.

Built like a product, documented like a toolkit.

Portalens rolle er å gjøre Vedoy Connect lett å forstå for utviklere, drift og kunder uten å eksponere hemmeligheter.

Expo mobile

Development build, Voice SDK support, dark industrial Vedoy UI and mobile app shortcuts.

Node API

Express, TypeScript, helmet, CORS, rate limits and webhook validation.

Supabase

Auth JWTs, RLS-backed tables, private KYC storage and server-side service role only.

Vercel ready

Static portal and API docs can be published as a preview or production deployment when project binding exists.

Live state stays honest.

Dette feltet er bevisst tydelig: siden viser hva koden støtter lokalt, og hva som må kobles før den kan kalles live.

Local source

API-listen kommer fra `outputs/server/src` og Supabase-migrasjonen i dette prosjektet.

BackendImplementert, ikke bekreftet deployet fra denne mappen.
DatabaseSchema finnes lokalt. Live Supabase project id trengs for å hente faktisk tabellstatus.
SecretsTwilio og Supabase service role skal fortsatt ligge server-side.
Production gates

Før kjøp, SMS og samtaler aktiveres offentlig må eksterne systemer kobles og testes.

VercelKrev `.vercel/project.json` eller valgt project id før deployment.
TwilioWebhook-URL, Voice app, geo permissions, push credentials and regulatory mapping.
BillingTwilio-kostnader håndteres, men kundeabonnement/invoice-flow er ikke lagt inn.
